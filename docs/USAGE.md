# BiliMemo 使用说明

Chrome 扩展：正常浏览视频评论区时，将进入视口的评论记录到本机 SQLite；以后鼠标停留在用户头像上，即可查看此人在其他视频下被本机记录的发言，点击视频标题打开原视频。

## 安装

当前版本 **0.3.3**。更新时保留原来的 dist 路径，在 Chrome / Edge 扩展页点击「重新加载」，再刷新已经打开的 B 站页面。不要卸载旧扩展后重新安装。

从 0.1.0 更新时，首次打开会自动重建更小的搜索索引，保留所有评论；大数据库可能需要等待数十秒。完成后进入「数据管理」点击 **「压缩数据库」**，才会把索引升级留下的空闲空间还给磁盘。从 0.2.0 更新无需迁移数据库。

1. 打开 Chrome 的 `chrome://extensions` 页面，开启右上角「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 **dist** 文件夹（不是项目根目录）。
3. 刷新已经打开的 B 站视频页，正常滚动到评论区。右下角显示记录状态。
4. 将鼠标停留在评论头像上约 300 毫秒，查看本机历史记录。
5. 点击扩展图标，再点击「打开本地评论库」，可搜索、暂停记录或备份。

源码构建：需要 Node.js 22.18+（测试使用 Node.js 24.4.1），运行 `npm ci`、`npm run build`。分发给他人时只需提供 dist 文件夹；无需 Node、Python 或数据库服务。

## 已实现

- 普通 BV 视频页的一级评论、可见楼中楼回复；支持当前 B 站多层 Shadow DOM，包括 Chrome 可访问的封闭 Shadow Root。
- 进入视口后记录，页面隐藏时不采集；用户手动展开、滚动、切换排序后增量记录。扩展不自动翻页、展开回复、访问用户空间或调用评论接口。
- 头像悬浮与键盘聚焦查询，默认排除当前视频；支持切换、分页、Esc 关闭和原视频标题超链接。
- 可见评论的 LV 等级后自动显示「其他视频 N 条」和最近记录的视频标题链接，无需逐个悬浮；缺少等级时显示在用户名后。条数和最近记录的视频链接均排除当前视频，同一条评论重复采集不重复计数；最近记录按评论首次进入本机数据库的时间排序（不是最新发表时间）。没有记录显示 0 条；查询失败单独显示错误，不冒充零记录。
- 按 UID、昵称、BV 号、评论内容及本机记录日期查询。
- 记录开关、删除指定用户、清空数据库、无损数据库整理、标准 SQLite 导出和合并导入。
- 所有脚本、样式和 SQLite WASM 随扩展打包；无云端同步、远程代码、遥测或额外头像请求。

## 数据与性能

数据库保存在扩展自身源的 OPFS 中，通过唯一的数据库 Worker 服务多个标签页。昵称和视频标题独立保存，评论使用整数外键；站点 UID、BV、评论 ID 保留字符串，避免精度损失。

头像查询通过覆盖候选字段的联合索引定位少量评论，再读取正文。历史使用二元游标分页；统计与评论在同一事务内维护；Worker 缓存有 200 条/8 MiB 上限，写入后失效。中文长关键词全库检索使用 FTS5 trigram；指定 UID/BV 或输入 1–2 字关键词时，先按索引缩小范围，再按有界批次扫描，用户可点击「继续检索下一批」。关键词按字面子串匹配、区分大小写。查询过慢时会中断并提示缩小范围。

数据写入通过短事务完成，只有提交后才确认成功；重复发送不重复计数。浏览器异常退出前尚未确认的记录可能丢失。性能测量范围和结果见 [PERFORMANCE.md](../PERFORMANCE.md)。

评论旁的摘要仅查询可见用户，200 毫秒合并请求、同 UID 去重、每批最多 50 个，一条固定 SQL 使用用户统计表和现有用户时间覆盖索引，不读取评论正文，也不新增索引或持久化字段。每页最多缓存 300 个用户、有效期 30 秒；本页成功采集后立即失效刷新，其他标签页写入、管理页删除或导入后，摘要会在重新可见或下一轮缓存到期时更新。页面隐藏时不查询，暂停采集不影响本地查询。

0.2.0 的全文索引不存词语位置和文档词数（`detail=none,columnsize=0`），查询先匹配三字符片段，再核对原文中的完整字面内容。评论正文、用户关联和时间记录不变。百万条合成库经升级和整理后约 297.6 MiB，相比旧版约 424.5 MiB 减少约 30%；实际收益取决于内容和碎片情况。

## 备份与数据清理

- 「导出 SQLite 备份」生成标准 `.sqlite3` 文件，可用桌面 SQLite 工具打开；当前单次导出和导入上限为 **256 MiB**，避免整库快照造成过高内存占用。
- 导入兼容本扩展数据库版本 1 和 2。先检查文件、版本和记录，再分批合并；重复记录去重，损坏文件不覆盖原库。若合并途中中断，已经提交的新记录保留，重新导入可继续。新版导出的数据库需使用 0.2.0 或更新的兼容版本导入。
- 数据库保留在当前 Chrome 配置及扩展 ID 下。卸载、清除扩展存储或改变扩展 ID/安装路径可能导致旧数据无法访问。更新时保留原来的 dist 路径并点击扩展的「重新加载」，不要先卸载。
- 删除用户记录后，再次浏览其评论仍可能记录。暂停只停止新记录，历史仍可查询。
- 「压缩数据库」会合并全文索引段并整理 SQLite 页面，不删除评论。升级或批量删除后可手动执行；需要额外临时磁盘空间，期间数据库查询和写入会等待，请保持扩展运行。日常浏览不自动执行全库整理。
- 占用卡片显示文件总大小与整页空闲空间。页内碎片未计入该空闲数字，因此显示空闲为零时，整理仍可能节省空间；整理后为后续写入留出的空闲页也可复用。

## 查询故障恢复

0.3.1 兼容仍在运行的旧版后台：当批量查询接口尚不可用时，自动使用原有历史查询，最多同时处理两个用户。数据库或连接错误保留具体原因，可将鼠标停留在提示上查看；不会把错误显示为零记录。显示「请刷新 B 站页面」时刷新视频页；显示「请重新加载扩展」时，先在扩展管理页重新加载，再刷新视频页，无需卸载。

## 当前限制

- 仅支持桌面普通 BV 视频页；番剧、直播、动态、移动版及无痕窗口不在本版范围内。最低 API 版本设为 Chrome 116，实际验证版本为 Chrome 152。
- 真实页面样本来自未登录状态，可见一级评论和默认展示的回复已验证。更多登录态、手动展开深层回复、旧版评论布局仍可能需要适配；页面改版时状态可能停留在「等待可见评论」。
- 当前新评论组件通常不在 DOM 中提供评论 ID，因此采用 UID、正文和楼层上下文指纹去重。相同上下文中的相同发言可能合并，正文折叠展开或编辑后也可能形成不同指纹；界面明确标记「指纹去重」。
- 发表时间只解析完整日期（按北京时间）；相对时间保留原文，不拿采集时间冒充发表时间。首次记录排序使用本机时间。
- 提供的是原视频链接，未实现精确跳转到某条评论。旧视频可能被删除或受访问限制。
- 本机没有记录不代表该用户没有发言；本机记录也不代表用户全部历史。是否触发 B 站风控取决于网站，扩展不作保证。

## 验证命令

```powershell
npm run check
npm test
npm run build
npx playwright install chromium
npm run verify:browser
npm run bench
```

如果 Playwright 自带的 Chromium 无法启动，可在专用测试配置中使用已安装的 Chrome：

```powershell
$env:BILI_TEST_CHROME='C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run verify:browser
node scripts/verify-live.mjs
npm run bench
```

测试通过专用配置与 Chrome 官方 CDP 加载扩展，不操作用户日常浏览器配置。`verify-browser` 使用本地模拟网页验证可见性、头像卡片、多标签页、重启、备份与错误处理；`verify-live` 才访问真实 B 站样本页。基准使用独立测试数据库，不向扩展加入任何测试接口。

输出保存在 `output/playwright` 与 `output/benchmark`，未纳入 Git；数据库单元测试在 `tests`。脚本及中文文档均为 UTF-8。
